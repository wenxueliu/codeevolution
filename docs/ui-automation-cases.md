# CodeEvolution UI 自动化用例

## 1. 使用说明

本文将 [用户旅程](user-journey.md) 转换为可执行的 UI 自动化用例。用例覆盖 Web 控制台的核心主旅程、角色分支和异常旅程。

当前 UI 测试能力通过“代码问答 → UI 测试”使用本机 Kimi WebBridge 录制和回放；页面级自动化也可以使用 Vue/Vitest 或浏览器自动化框架实现。所有用例均应优先使用稳定的 `data-testid`、role/name 或 URL 断言，避免依赖 CSS 层级和动态文本。

## 2. 测试环境与数据

### 2.1 环境

- CodeEvolution Web 服务已启动。
- 前端已构建，能够访问 `/`。
- 测试环境使用独立 `CODEEVOLUTION_DATA_DIR`。
- 测试仓库至少包含一个可读取的 CodeGraph 数据库。
- 多仓用例将 `data/mall` 与 `data/mall-admin-web` 注册到同一个 Scope；若验证跨仓 HTTP 边，fixture 中需保留可识别的前端请求。
- LLM 用例配置测试模型；未配置 LLM 时执行对应失败分支。
- UI 录制用例准备允许访问的 `http://shop.test` 测试站点。

### 2.2 测试数据

| 数据 | 示例 |
|---|---|
| 单仓服务 | `mall` |
| 多仓成员 | `mall`、`mall-admin-web`（同一 Scope） |
| 仓库路径 | `<服务根目录>/data/mall`、`<服务根目录>/data/mall-admin-web` |
| API | `POST /api/orders` |
| API 处理函数 | `OrderController.create` |
| UI 测试目标 | `shop` / `http://shop.test` |
| UI 测试名称 | `创建商品` |

## 4. 详细用例

### UI-001 空状态进入添加代码仓

**前置条件**：系统中没有已注册仓库。

**步骤与断言**：

1. 打开 `/`。
2. 断言页面显示“还没有代码仓”。
3. 点击“添加代码仓”。
4. 断言注册表单出现“服务名称”和“代码仓绝对路径”。

**通过标准**：用户能从空状态直接进入注册流程，不需要猜测下一步。

### UI-002 注册单个代码仓

**前置条件**：目标路径存在且可访问。

**步骤与断言**：

1. 打开添加代码仓表单。
2. 输入服务名称 `mall`。
3. 输入绝对路径 `/tmp/fixtures/mall`。
4. 点击“注册代码仓”。
5. 断言列表出现 `mall` 卡片。
6. 断言卡片显示仓库路径和索引状态。
7. 断言不会修改目标仓库文件。

**通过标准**：注册成功，且用户能看到该仓库当前是否具备分析条件。

### UI-003 首次运行分析自动初始化索引

**前置条件**：仓库已注册但显示“未初始化索引”。

**步骤与断言**：

1. 在 Snapshots 页选择该成员并点击“运行分析”。
2. 断言创建 Analysis Run，且成员 Attempt 的首个阶段为“初始化 CodeGraph”。
3. 断言页面轮询并依次显示初始化/同步、冻结、分析、发布等阶段。
4. 等待 Run 成功。
5. 断言成员出现已发布 Snapshot。
6. 刷新页面，断言 Snapshot 仍存在。

**失败分支**：CodeGraph 初始化或同步失败时，断言显示失败阶段、错误信息和仅重试该成员的入口。

### UI-004 运行分析并生成 Snapshot

**前置条件**：至少一个成员索引就绪。

**步骤与断言**：

1. 进入 `Snapshots` 页面。
2. 点击“运行分析”。
3. 断言创建分析任务，记录 Run ID，并显示运行中的成员状态。
4. 等待任务完成。
5. 断言成员显示 Snapshot ID 和“已发布”。
6. 断言失败仓库不会覆盖已有成功 Snapshot。

**通过标准**：只有用户主动点击后才产生新的分析结果。

### UI-005 创建 Graph View 并进入知识中心

**前置条件**：至少一个成员有当前 Snapshot。

**步骤与断言**：

1. 进入 `Snapshots` 页面。
2. 点击“创建当前 View”。
3. 断言页面显示 View ID 和摘要。
4. 点击“查看知识”。
5. 断言 URL 带有 `snapshot_id`。
6. 断言知识中心显示当前 Snapshot ID。

**通过标准**：知识页使用已发布 Snapshot，而不是直接读取现场代码。

### UI-006 浏览 API 契约和调用链

**前置条件**：Snapshot 中存在 `POST /api/orders`。

**步骤与断言**：

1. 进入知识中心。
2. 点击“API 契约”。
3. 断言显示端点数量。
4. 使用路径搜索 `orders`。
5. 点击 `POST /api/orders` 行。
6. 断言展开请求、响应、参数和处理函数信息。
7. 断言显示后端调用链树。
8. 展开时序图。
9. 断言 Mermaid 图可见，且可打开放大查看。

### UI-007 生成 API 功能解释

**前置条件**：LLM 已配置；目标 API 有处理函数、文件和行号。

**步骤与断言**：

1. 展开目标 API。
2. 点击“生成 API 功能解释”。
3. 断言显示“生成中”状态。
4. 等待异步任务结束。
5. 断言显示业务摘要和业务流程。
6. 断言显示节点完成数、总数和覆盖率。
7. 点击“管理快照”。
8. 断言解释快照列表显示生成记录。

**失败分支**：生成失败时，断言显示失败状态和错误信息，不影响结构化知识浏览。

### UI-008 配置并测试 LLM

**前置条件**：使用独立测试配置目录。

**步骤与断言**：

1. 点击顶部“LLM 设置”。
2. 输入模型、API Base 和 API Key。
3. 保存设置。
4. 断言保存成功提示。
5. 点击“测试连接”。
6. 断言显示连接成功。
7. 重新打开设置。
8. 断言 API Key 不以明文回显。

### UI-009 使用代码问答并查看审计日志

**前置条件**：已进入某个代码仓知识页。

**步骤与断言**：

1. 点击右侧“代码问答”。
2. 输入“谁调用了 createOrder”。
3. 发送问题。
4. 断言显示回答。
5. 展开“查看执行操作”。
6. 断言显示受控操作名称，不显示任意 SQL。
7. 切换到“审计日志”。
8. 断言显示问题、操作、结果数量和耗时。

### UI-010 录制并回放 UI 测试

**前置条件**：目标 origin 已允许访问，WebBridge 可用。

**步骤与断言**：

1. 打开“代码问答 → UI 测试”。
2. 输入测试名称“创建商品”。
3. 输入目标名称 `shop`。
4. 输入目标地址 `http://shop.test`。
5. 点击“打开并开始录制”。
6. 断言状态显示正在录制，并打开独立标签页。
7. 在目标页面执行输入、点击和保存操作。
8. 等待步骤同步。
9. 点击“停止录制”。
10. 断言记录状态为已录制，并显示步骤数和接口请求数。
11. 点击“回放”。
12. 断言运行状态为 `passed`。

### UI-011 添加 UI 检查点并验证回放

**前置条件**：存在进行中的录制。

**步骤与断言**：

1. 添加“文本可见”检查点，例如“保存成功”。
2. 添加“URL 包含”检查点，例如 `/orders`。
3. 添加“接口应答”检查点，例如 `/api/orders 201`。
4. 停止录制。
5. 回放测试。
6. 断言记录中包含三个检查点。
7. 断言成功时显示 `passed`；失败时显示失败原因和截图信息。

### UI-012 多仓部分失败后单独重试

**前置条件**：`mall` 和 `mall-admin-web` 已注册到同一个 Scope；人为让一个成员分析失败。

**步骤与断言**：

1. 选择两个成员并运行分析。
2. 等待任务结束。
3. 断言总体状态为部分成功或相应的非全成功状态。
4. 断言成功成员发布新 Snapshot。
5. 断言失败成员保留旧 Snapshot 或显示无新 Snapshot。
6. 修复失败成员环境。
7. 对失败成员单独重试。
8. 断言重试成功后仅更新该成员的 current Snapshot。

### UI-013 LLM 未配置时保持结构知识可用

**前置条件**：未配置 LLM；Snapshot 已存在。

**步骤与断言**：

1. 进入知识中心。
2. 断言 API 契约、模块拓扑和核心实体可正常加载。
3. 点击“抽取 LLM 知识”。
4. 断言出现配置提示或调用失败提示。
5. 断言页面仍可切换和查看结构化知识。

### UI-014 网络错误后重试页面加载

**前置条件**：模拟 `/api/repos` 或 `/api/knowledge` 请求失败一次。

**步骤与断言**：

1. 打开对应页面。
2. 断言显示错误状态、错误标题和“重试”按钮。
3. 恢复 API。
4. 点击“重试”。
5. 断言页面加载成功，错误状态消失。

### UI-015 刷新后保持 Snapshot / View 语义

**前置条件**：已创建 View，并在知识中心打开某个 API。

**步骤与断言**：

1. 记录当前 Snapshot ID、View ID 和 API 展开状态。
2. 在后台为同一成员生成新 Snapshot。
3. 不点击“刷新最新结果”，直接刷新当前知识页。
4. 断言当前页面仍显示原 View / Snapshot，且知识/调用链请求携带该身份。
5. 返回 Snapshots 页面并创建新 View。
6. 再进入知识中心。
7. 断言页面显示新的 Snapshot / View。

### UI-016 分析 Run 的进度、取消与失败成员重试

**前置条件**：同一 Scope 中有 `mall` 和 `mall-admin-web`；其中一个成员可被配置为失败。

1. 选择两个成员并运行分析，断言每个成员有独立 Attempt 和阶段。
2. 在运行中取消一个成员，断言其终态为 `cancelled`，另一个成员仍继续并可发布。
3. 使一个成员失败，断言已成功成员的 current Snapshot 不变，失败成员显示错误阶段。
4. 点击失败成员的“重试”，断言新 Run 只包含该成员，成功后只更新该成员的 current Snapshot。

### UI-017 多仓 View 的拓扑、影响与流程追踪

**前置条件**：`mall` 和 `mall-admin-web` 都已生成 Snapshot；fixture 包含至少一条可识别的前端 HTTP 调用或服务依赖。

1. 选择两个成员并创建 Graph View，断言 View ID、成员 Snapshot ID 和 digest 可见。
2. 打开该 View 的拓扑，断言至少一条依赖边及其入口、调用位置和匹配证据可见。
3. 选择一项服务查看影响范围，断言上游/下游服务与证据一致。
4. 从同一服务查看流程，断言 HTTP（及 fixture 具备时的 MQ/Redis）通道和路径顺序可见。

### UI-018 显式检查改动并切换旧/新快照

**前置条件**：成员存在已发布 Snapshot。

1. 修改 fixture 的一个可识别输入后点击“检查改动”。
2. 断言状态为 `source_changed`；该操作不创建 Snapshot。
3. 运行新的 Analysis Run，断言产生新 Snapshot，旧 Snapshot 仍可打开。
4. 创建新 View 并切换到它，断言新旧 View 的成员 Snapshot 映射不同。

## 6. 自动化实施建议

### P0 冒烟集

优先自动化：`UI-001`、`UI-002`、`UI-003`、`UI-004`、`UI-005`、`UI-006`、`UI-010`、`UI-012`、`UI-016`、`UI-017`。

这组用例覆盖从空状态到分析、知识浏览、UI 测试和多仓失败恢复的最短闭环。

### P1 回归集

自动化：`UI-003`、`UI-007`、`UI-008`、`UI-009`、`UI-011`、`UI-013`、`UI-014`、`UI-015`。

### 稳定定位策略

- 优先使用 `data-testid`，其次使用 accessible role/name。
- API 请求使用 mock 或测试后端，避免依赖真实模型、真实仓库和不稳定网络。
- 异步分析使用状态轮询和明确的终态断言，不使用固定长时间 sleep。
- 每个测试使用独立 `CODEEVOLUTION_DATA_DIR`，避免 Snapshot、审计日志和录制数据互相污染。
- LLM、WebBridge 和目标网站分别提供 stub；只保留一条端到端用例验证真实集成。
- 用例失败时保存浏览器截图、当前 URL、关键 API 响应和录制 DSL。
